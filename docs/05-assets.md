# 05 — Brand Assets

Where every image and font on the Funky Fresh Farm site comes from, how it is stored, where it
renders, and how to replace it. The visual system that uses these assets is in
[05-design-system.md](05-design-system.md).

## 1. Two kinds of assets

| | Git-managed static assets | CMS-managed media |
|---|---|---|
| What | Brand artwork that belongs to the *design*: emblem, hero, story, guide and 404 illustrations, sticker, social card, fonts | Editorial images chosen per page: the plant illustrations |
| Stored in | `src/FunkyFreshFarm.UmbracoLab/wwwroot/brand/` and `wwwroot/fonts/` (committed) | Umbraco Media Library: files in `wwwroot/media/` (untracked), metadata in the database |
| Referenced by | Fixed paths in Razor templates and CSS | The **Plant Image** property (`plantImage`, Image Media Picker) on each Plant Page |
| Served by | ASP.NET Core static files, as generated | `/media/...` through ImageSharp: signed (`hmac`), resized, cropped square, converted to WebP on request |
| Changed by | A developer: rerun `scripts/Build-BrandAssets.ps1`, commit | An editor in the backoffice: upload, choose, **Save and publish** |
| Deployed by | Git | Database + `wwwroot/media/` (backup/restore, see 04-architecture.md §10) |

The hero, story, and guide illustrations are treated as brand artwork (Git) rather than
editorial content, to avoid Document Type changes for images editors do not need to swap.
Making one editor-replaceable later means adding an Image Media Picker property and moving the
file into the Media Library.

## 4. CMS-managed plant illustrations

The three botanical prints are square, painted edge to edge on Warm Cream. They are uploaded to the
Media Library **as originals** (the master copy) and assigned to each Plant Page's **Plant Image**.
Razor (`Views/Partials/PlantIllustration.cshtml`) requests signed, square WebP crops:

| Where | Widths in `srcset` | `sizes` | Crop |
|---|---|---|---|
| Plant cards (home, directory) | 320, 480, 640, 800 | `(min-width: 64rem) 22rem, (min-width: 48rem) 45vw, 92vw` | Square (`ImageCropMode.Crop`, width = height); a square original is not cropped |
| Plant profile | 480, 720, 960, 1254 | `(min-width: 70rem) 33rem, (min-width: 48rem) 46vw, 92vw` | Square |

Example URL: `/media/<folder>/<file>.png?width=640&height=640&format=webp&quality=80&v=…&hmac=…`.
`format` and `quality` are part of the signed query, so tampering returns 400. A non-square upload
is centre-cropped (or cropped around the editor's focal point). Plants without an image show the
"No image yet" placeholder card, and the profile page omits the figure.

## 5. Owner procedures (manual)

**Status: all three completed by the owner** (plant images published 2026-11-16, farm story
published 2026-11-17) and verified read-only; see the Milestone 5 section of
[verification-log.md](verification-log.md). The procedures stay here for recreating the site from a
fresh database.

### MT-27: Upload the botanical illustrations to the Media Library

| | |
|---|---|
| **Purpose** | Put the three botanical prints into the Media Library so pages can reference them; the Media Library copy is the editorial master |
| **Starting location** | Backoffice → **Media** section; files in `C:\dev\FunkyFreshFarm\assets\images\` |
| **Stop point** | Continue to MT-28 |

| Media item name | File to upload | Parent |
|---|---|---|
| `Heirloom Tomato illustration` | `Vintage Heirloom Tomato Vine.png` | Plants |
| `Basil illustration` | `Vintage Botanical Basil Print.png` | Plants |
| `Zinnia illustration` | `Retro Zinnia Bouquet Screen Print.png` | Plants |

1. Select **Media**, hover the **Plants** folder → **…** → **Create** → **Image**.
2. Enter the name from the table; in the file area **Click to upload** and choose the file.
3. **Save**. Repeat for the other two.

**Expected:** six images in Media → Plants (three placeholders, three illustrations).
**Troubleshooting:** if an upload is rejected, check the file is the PNG from `assets\images\` (PNG is an allowed image type).

### MT-28: Assign the illustrations to the plant pages

| | |
|---|---|
| **Purpose** | Replace the placeholders; Zinnia gets an image for the first time |
| **Starting location** | Backoffice → **Content** section |
| **Stop point** | Continue to MT-29 |

1. Open **Plants → Heirloom Tomato**. In **Plant Image**, remove the current image (the remove control on the picked item), then **Choose** → **Plants** → **Heirloom Tomato illustration** → confirm.
2. **Save and publish**.
3. Repeat for **Basil** (Basil illustration) and **Zinnia** (Zinnia illustration).

**Expected:** each plant page and card shows the botanical print; the console logs a
`Published plantPage …` line per plant (Milestone 3 handler).
**Verification:** `pwsh ./scripts/Test-BrandAssets.ps1` reports the three "Botanical" checks as PASS.

### MT-29: Add the farm-story properties and content

| | |
|---|---|
| **Purpose** | Give the homepage's farm-story section editor-managed text. The template already reads these properties and hides the section until `storyText` has a value |
| **Starting location** | Backoffice → **Settings** → **Document Types** → **Home Page** |
| **Stop point** | Continue to MT-30 |

| Property name | Alias | Data Type | Mandatory |
|---|---|---|---|
| Story Heading | `storyHeading` | Textstring | Off |
| Story Text | `storyText` | Textarea | Off |

1. On **Home Page** → **Design** → in the **Content** group, **Add property** twice with the table's values (pick Data Types under **Available configurations**), **Submit** each, then **Save**.
2. Open **Content → Home**, fill the two fields (values below), **Save and publish**.

Story Heading:

```text
Grown by hand, shared with joy
```

Story Text (two lines):

```text
Funky Fresh Farm began with a few raised beds, a borrowed watering can, and a stubborn love of heirloom seeds.
Today we still grow everything the slow way: healthy soil, plenty of sunshine, and a little bit of funk.
```

**Expected:** the homepage shows a Mint "story" panel with the garden illustration below the featured plants.
**Why the template does not break before this step:** it reads `Model.Value<string>("storyText")`,
which returns null for a property that does not exist yet, instead of the generated
`Model.StoryText`, which would not compile until the property exists (InMemoryAuto).

## 6. Replacing assets later

- **Brand artwork (Git):** replace the original in `assets/images/` (same name, or edit the table at
  the top of `scripts/Build-BrandAssets.ps1`), run
  `powershell -ExecutionPolicy Bypass -File scripts\Build-BrandAssets.ps1`, update the expected
  dimensions in `scripts/Test-BrandAssets.ps1` if the aspect ratio changed, check the pages, commit.
  Browsers may cache old files; filenames are stable, so hard-refresh (Ctrl+F5) during development.
- **Plant illustrations (CMS):** upload the new image to Media → Plants and pick it in the plant's
  **Plant Image**; Save and publish. No code change. Prefer square images; otherwise set a focal point.
- **Fonts:** download new WOFF2 files and their licence, keep the filenames or update `@font-face`
  in `site.css` and the preload links in `_Layout.cshtml`.
